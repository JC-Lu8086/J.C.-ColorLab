# 操作流程

## 准备屏幕和相机

使用实际要作为相对基准的显示器；记录屏幕型号、ICC 配置、亮度设置、相机型号、镜头、曝光与白平衡。关闭会随环境改变颜色/亮度的功能，使用 SDR。更换这些条件后，重新拍摄并生成映射。

屏幕预热至稳定后显示本项目色卡。用稳定支撑让相机尽量正对屏幕，保持足够距离并选择合适焦距，让四角定位标记完整入镜。检查反光、屏幕刷新条纹与像素摩尔纹；必要时调整距离、快门和构图。目标是获得均匀、未剪切、每块内部有足够像素的采样区域。

推荐使用至少 3840 × 2160 的 4K 屏幕，以 15 英寸笔记本为设计参考，选择默认 376 色（343 个 RGB 网格色 + 33 级灰阶）。照片模糊、有噪声或采样块像素不足时退回 146 色。4978 色属于实验模式，不推荐用于 15 英寸 4K 屏幕的常规校色。所有色块都有黑色间隔，相近颜色会被分散排列，但这不能替代清晰、足够分辨率的拍摄。

## 分别选择屏幕目标与工作空间

屏幕目标可选 sRGB、Display P3、Adobe RGB (1998)。不确定屏幕能力时先选 sRGB；P3/Adobe RGB 目标需要显示器具备相应覆盖、有效的显示 ICC 和正确的浏览器色彩管理。选择宽色域选项本身不是屏幕测量，也不会阻止超出屏幕能力的颜色被裁切。

照片工作域另行选择 sRGB、Adobe RGB (1998)、Display P3、ProPhoto RGB 或 ACEScg。普通 Photoshop 流程可先选 sRGB；已有明确宽色域流程时选择对应空间。ACEScg 只用于 AP1 / D60 / 线性 0–1 数值域，本版不提供完整 ACES/HDR 流程。软件会把屏幕参考转换到工作域；ProPhoto 和 ACEScg 不作为声称能被屏幕完整显示的目标。

改变屏幕空间、密度或工作域后应重新导入图片并拟合；旧照片要与拍摄时的色卡配置对应。CUBE 注释、报告和模型保存工作域，后续应用时需要一致。屏幕目标之外的颜色属于外推，不能依据训练误差宣称全工作色域准确。

若屏幕参考中有颜色不能表示在所选工作域的 0–1 数值范围，校色时会自动排除这些块并报告数量。检查排除情况和样本覆盖后再导出；选择一个更宽的空间名称并不保证它包含另一空间的全部边缘颜色。

## 屏幕相对校色

1. 在色卡页选择目标空间与密度，并完整显示色卡；保存对应的参考信息。
2. 拍摄相机最高画质 JPG，或者导入 RAW；也可在你日后实际使用的显影软件中，以固定设置输出带正确 ICC 的 TIFF。JPG 建模与后续应用需使用同一相机直出设置和明确的颜色空间。
3. 在校色模式导入图片。当前版本自动识别的是 JC ColorLab 自己的定位标记。
4. 检查自动定位后的点位。每个点应位于对应色块的内部，远离黑色间隔、标记和反光；识别不成功时使用手动定位工具。
5. 计算映射，查看异常提示、训练/留出误差以及图像预览。误差很大时先检查点位、色卡版本、曝光和输入色彩空间，避免仅靠提高拟合复杂度补偿坏数据。
6. 在拍摄备注中记录显示器、ICC、亮度、相机、白平衡和曝光；这些备注随报告保存。保存模型、报告和 CUBE，保留原片与处理设置，之后用相同链路处理其他图片。

不要用一张经过风格化、剪切或未标明色彩空间的截图作为“绝对标准”反向校正相机。

## 从相机直出重建风格

1. 固定拍摄条件，获得同一色卡的基准图与风格图。优先使用同一次 RAW+JPEG 拍摄，避免曝光、白平衡和构图变化。
2. 基准可以是中性直出 JPG，或固定显影的 RAW；目标是相机风格直出 JPG。使用明确、固定的显影方式，并将两图转换到同一个工作域。相机 JPG 推荐保留正确的 sRGB 或 Adobe RGB 描述，避免把 Adobe RGB 数值误当 sRGB；没有 ICC 时确认软件的来源假设。
3. 选择风格模式，分别导入两张照片并分别检查定位。软件按同一色块身份配对，不要求两张照片有相同像素坐标。
4. 拟合方向为 **基准图 → 风格图**。这一步不是求风格的数学逆变换。
5. 查看灰阶和高饱和色块的表现；用人像、自然景物和未参与拟合的照片验证，再保存风格 CUBE。

如果基准图已经经过本项目校色，拟合和实际应用都必须使用同一校色结果作为输入；不要在使用时遗漏或重复这一前置变换。相机局部色调、颗粒和锐化不会被 CUBE 重建。

## 在 Photoshop 中应用 CUBE

1. 用生成 LUT 时相同的显影链路得到照片。若基准来自本软件的 RAW 显影，先使用「显影原片 TIFF（未应用映射）」导出，再在 Photoshop 中应用 CUBE / XMP 一次；「校正后 TIFF」已经应用映射，不能重复套用。
2. 通过 Photoshop 的 **转换为配置文件**将图片转换到 **LUT 对应的工作空间**。例如 sRGB LUT 需要 sRGB，Adobe RGB LUT 需要 Adobe RGB (1998)。不要仅“指定”配置文件；指定会改变数值解释而不做正确转换。ACEScg 需要宿主中正确配置的线性 AP1 工作流，不能用 sRGB 或普通 gamma 配置替代。
3. 新建 **颜色查找 / Color Lookup** 调整图层，选择 **载入 3D LUT**，加载 `.cube`。
4. 把调整图层放在与拟合时一致的处理位置，检查高光、阴影和肤色，再决定是否改变图层强度。
5. 保存时嵌入正确的输出 ICC；需要其他输出色域时，在完成此变换后按你的工作流转换。

CUBE 本身没有完整的 ICC 色彩管理语义，宿主软件不会自动知道它要求的输入域。把 LUT 套到不同的 RGB 编码、Log、HDR 或不同基础显影上，可能明显偏色。Adobe 对颜色查找的功能说明见 [Photoshop Color Lookup](https://helpx.adobe.com/photoshop/using/match-replace-mix-colors.html)。

## Adobe XMP

XMP 是元数据容器，既可承载调整预设，也可承载配置文件。一个普通曲线预设不能自动表示任意 3D LUT。

当前 XMP 使用嵌入 32³、16 位 3D LUT 的实验性 Adobe 创意配置文件格式，不是仅有独立通道曲线的预设，默认强度为 1。具体 RGB 表空间与工作域转换方式见 [Adobe XMP 格式说明](ADOBE_XMP_FORMAT.md)。配置文件限定用于**已经显影的 SDR TIFF/JPEG**，例如 Photoshop 的 Camera Raw 滤镜；它不会作为适用配置文件出现在未显影 RAW 上。直接给 RAW 使用会把 LibRaw 与 Adobe 两种基础显影混为同一个输入，所以本版本主动限制这种用法。

sRGB、Adobe RGB (1998)、Display P3 和 ProPhoto RGB 使用对应的原生 RGB 表定义；Adobe RGB 的精确 gamma 563/256 与 ProPhoto 暗部线性段通过表格中的曲线适配保留。ACEScg 没有在此直接嵌入为原生 Adobe RGBTable；它通过 sRGB 适配表导出，涉及范围限制与可能的裁切，因此不能把该 XMP 当作原生 ACEScg CUBE 的全域等价物。需要保留原始 ACEScg 工作域时使用 CUBE，并在正确配置的宿主中应用。

独立解码测试已经检查完整表格、内容键和格点顺序，但尚未完成 Adobe Camera Raw / Lightroom 宿主导入及渲染一致性验证。请同时保留 CUBE 与 JSON 报告；不能仅凭文件能被读取就宣称其色彩处理与 Photoshop CUBE 完全等价。详细导入方式与证据见 [Adobe XMP 格式说明](ADOBE_XMP_FORMAT.md)。

Adobe 的 [Camera Raw 配置文件安装说明](https://helpx.adobe.com/camera-raw/desktop/edit-and-enhance-images/tone-and-color/adjust-color-rendering-camera-camera.html)介绍了配置文件与预设导入；[Camera Raw 工作流说明](https://helpx.adobe.com/camera-raw/desktop/get-started/overview-and-setup/camera-raw-settings.html)说明输出位深和色彩空间的关系。

## 出现问题时

| 现象 | 优先检查 |
|---|---|
| 识别不到 | 四个标记是否完整、图像是否过小/模糊；是否选择了同一空间与密度的色卡 |
| 点落在间隔或邻块 | 重新定位，并降低色卡密度或提高拍摄有效分辨率 |
| 校正后颜色反而异常 | 输入色彩空间、LUT 方向、RAW 显影链路以及是否重复应用映射 |
| 高光/阴影突然断层 | 原片或目标图是否剪切；检查曝光，重新拍摄 |
| 灰阶不均或出现彩色纹 | 屏幕刷新、摩尔纹、环境反光、自动亮度或相机白平衡变化 |
| 训练误差好、留出误差差 | 覆盖不足、过拟合、错误样本或单张图无法约束目标风格 |
| Windows 无法运行 | 记录 Windows 版本、CPU、Python/应用版本和错误信息；该平台目前依赖社区协助 |

提交问题时，请优先附最小可复现样例、导出的报告与相应处理设置；不要把私密原片直接放入公开仓库。
